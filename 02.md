# Problem Title: Fibonacci Series using Memoization (LeetCode 509)

## Problem Statement
The **Fibonacci sequence** is a sequence of numbers where each number is the sum of the two preceding ones, starting from $0$ and $1$.

Mathematically:
- $F(0) = 0$
- $F(1) = 1$
- $F(n) = F(n - 1) + F(n - 2)$ for $n \ge 2$

Given an integer `len`, generate and print the first `len` terms of the Fibonacci sequence.

---

## Sample Examples

### Example 1
- **Input:** `len = 6`
- **Output:** `0 1 1 2 3 5`
- **Explanation:**
  - Term 0: $0$
  - Term 1: $1$
  - Term 2: $0 + 1 = 1$
  - Term 3: $1 + 1 = 2$
  - Term 4: $1 + 2 = 3$
  - Term 5: $2 + 3 = 5$

### Example 2
- **Input:** `len = 2`
- **Output:** `0 1`
- **Explanation:** Only the first two terms are requested, which are $F(0) = 0$ and $F(1) = 1$.

### Example 3
- **Input:** `len = 8`
- **Output:** `0 1 1 2 3 5 8 13`
- **Explanation:** The sequence continues: $F(6) = 3 + 5 = 8$, $F(7) = 5 + 8 = 13$.

---

## Detailed Solution (In Simple English)

### 1. Intuition & Approach
The standard naive recursive way to compute Fibonacci numbers is:
```cpp
fibo(n) = fibo(n - 1) + fibo(n - 2)
```
However, naive recursion re-calculates the exact same terms over and over again. For example, to calculate `fibo(5)`, `fibo(3)` is computed multiple times in separate branches. This causes the time complexity to blow up exponentially to $O(2^n)$.

To fix this, the solution uses **Memoization** (Top-Down Dynamic Programming):
- We keep a memory table (an array called `fibonaccci[]`).
- Whenever we compute the $n$-th Fibonacci number for the first time, we store it in `fibonaccci[n]`.
- If the function is asked for `fibo(n)` again in the future, we simply look it up in `fibonaccci[n]` immediately in $O(1)$ time instead of recomputing it!

---

### 2. How the C++ Code Works Step-by-Step

```cpp
#include<iostream>
#define MAX 100
using namespace std;

int fibonaccci[MAX];

int fibo(int n) {
    if(n==0) 
        return 0;
    if(n==1) 
        return 1;

    if(fibonaccci[n] != 0) {
        return fibonaccci[n];
    }

    return fibonaccci[n] = (fibo(n-1) + fibo(n-2));
}

int main() {
    int len;
    cout << "Enter len of fibo : " << endl;
    cin >> len;

    for(int i=0; i<len; i++) {
        cout << fibo(i) << " ";
    }

    return 0;
}
```

1. **Global Cache Array**:
   - `int fibonaccci[MAX];` defines an array of size 100 initialized to all zeroes (global arrays in C++ are zero-initialized by default).
2. **Base Cases**:
   - `if (n == 0) return 0;`
   - `if (n == 1) return 1;`
3. **Lookup Cached Result**:
   - `if (fibonaccci[n] != 0)` checks whether we have already calculated $F(n)$. If yes, it immediately returns the saved value.
4. **Compute and Save**:
   - `fibonaccci[n] = (fibo(n-1) + fibo(n-2));`
   - Calculates the sum of the previous two terms, stores the answer into `fibonaccci[n]`, and returns it.
5. **Driver Loop in `main()`**:
   - Reads `len` from user.
   - Loops from `i = 0` to `len - 1`, calling `fibo(i)` and printing each term followed by a space.

---

### 3. Step-by-Step Execution Walkthrough (Computing $F(4)$)

```
                       fibo(4)
                     /         \
              fibo(3)           fibo(2) -> [Reused from cache!]
             /       \
        fibo(2)     fibo(1)=1
        /     \
    fibo(1)=1  fibo(0)=0
```
- First, `fibo(2)` is computed as $1 + 0 = 1$ and saved: `fibonaccci[2] = 1`.
- Next, `fibo(3)` computes $F(2) + F(1) = 1 + 1 = 2$ and saves: `fibonaccci[3] = 2`.
- When `fibo(4)` needs `fibo(2)`, it does **not** recalculate it; it directly reads `fibonaccci[2] = 1`.
- Total computation is completed in linear steps without duplicate work!

---

### 4. Complexity Analysis

- **Time Complexity:** $O(\text{len})$  
  Because each value from $0$ to $\text{len}-1$ is computed only once and then cached, the total time spent across all calls is linear $O(\text{len})$ instead of exponential $O(2^{\text{len}})$.
- **Space Complexity:** $O(\text{len})$  
  - Cache table: $O(\text{MAX}) = O(1)$ fixed array.
  - Recursion call stack: up to $O(\text{len})$ levels deep.

---

### 5. Edge Cases & Notes
- **`len = 1`:** The loop runs once for `i = 0`, printing `0`.
- **`len = 0`:** The loop does not execute; nothing is printed.
- **Maximum Length:** `MAX` is defined as 100. If `len > 100`, it would cause an out-of-bounds error. Furthermore, standard integer types will overflow around $n = 47$, so for large Fibonacci numbers, `unsigned long long` or big integer representations are required.
