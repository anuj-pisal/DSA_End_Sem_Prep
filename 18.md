# Problem Title: Search an Element using Binary Search

## Problem Statement
Given a **sorted** array of integers and a `target` value, search for the `target` in the array using the **Binary Search** algorithm.

- If the element is present, report that the target is found.
- If the element is not found, report that the target is not present in the array.

> [!IMPORTANT]  
> Binary Search requires the array to be sorted. It works in logarithmic time $O(\log n)$, which is exponentially faster than Linear Search for large datasets.

---

## Sample Examples

### Example 1
- **Sorted Array:** `[1, 3, 4, 9, 10, 14, 19, 23]`
- **Input Target:** `9`
- **Output:** `Target is found in Array !`
- **Explanation:**  
  - Initial search space: indices `0` to `7`. Middle index is `3` (`arr[3] = 9`).
  - Target `9` matches `arr[mid]` immediately on the very first iteration!

### Example 2
- **Sorted Array:** `[1, 3, 4, 9, 10, 14, 19, 23]`
- **Input Target:** `15`
- **Output:** `Target is not present in the array !!`
- **Explanation:**  
  - Check `mid = 3` (`9`): $9 < 15 \rightarrow$ search right half `[10, 14, 19, 23]`.
  - Check `mid = 5` (`14`): $14 < 15 \rightarrow$ search right half `[19, 23]`.
  - Check `mid = 6` (`19`): $19 > 15 \rightarrow$ search left half.
  - Pointers cross (`l > h`), search space becomes empty. Target `15` does not exist.

### Example 3
- **Sorted Array:** `[1, 3, 4, 9, 10, 14, 19, 23]`
- **Input Target:** `1`
- **Output:** `Target is found in Array !`
- **Explanation:** Search narrows down to the leftmost element at index 0.

## Detailed Solution (In Simple English)

### 1. Intuition & Approach (The Dictionary Analogy)
Think of looking for a word in a physical dictionary:
- You don't read page 1, page 2, page 3... sequentially.
- Instead, you open roughly to the middle.
- If your word alphabetically comes **after** the words on that page, you ignore the entire left half of the dictionary.
- If your word comes **before**, you ignore the entire right half.
- In each step, you **cut the remaining search space in half**.

In Binary Search:
- Maintain two pointers: `l` (low/start) and `h` (high/end).
- Compute the midpoint: `mid = l + (h - l) / 2`.
- Compare `arr[mid]` with `target`:
  1. **Match:** `arr[mid] == target` $\rightarrow$ Found!
  2. **Target is bigger:** `arr[mid] < target` $\rightarrow$ Target must be in the right half, so set `l = mid + 1`.
  3. **Target is smaller:** `arr[mid] > target` $\rightarrow$ Target must be in the left half, so set `h = mid - 1`.
- Repeat as long as `l <= h`. If `l > h`, the search space has shrunk to zero without finding the target.

---

### 2. How the C++ Code Works Step-by-Step

```cpp
#include<iostream>
using namespace std;

int main()
{
    int arr[] = {1, 3, 4, 9, 10, 14, 19, 23};
    int n = sizeof(arr) / sizeof(arr[0]);
    int l = 0, h = n-1;
    int target;

    cout << "Enter target : ";
    cin >> target;

    while(l <= h) {
        int mid = l + (h-l) / 2;
        if(arr[mid] == target) {
            cout << "Target is found in Array !" << endl;
            return 1;
        }
        else if(arr[mid] < target) {
            l = mid+1;
        }
        else {
            h = mid-1;
        }
    }

    cout << "Target is not present in the array !!" << endl;

    return 0;
}
```

1. **Initialization**:
   - `int arr[] = {1, 3, 4, 9, 10, 14, 19, 23};` (8 elements, sorted).
   - `l = 0` (first index) and `h = n - 1 = 7` (last index).
2. **Reading Target**: User provides the search value.
3. **The Search Loop (`while (l <= h)`)**:
   - `int mid = l + (h - l) / 2;` computes the middle index safely without arithmetic overflow.
   - `if (arr[mid] == target)`: Prints found message and exits immediately via `return 1`.
   - `else if (arr[mid] < target)`: Discards the left half by advancing `l = mid + 1`.
   - `else`: Discards the right half by pulling back `h = mid - 1`.
4. **Target Not Found**:
   - If `l` exceeds `h`, the loop finishes and prints `"Target is not present in the array !!"`.

---

### 3. Step-by-Step Dry Run (Target = 19)

Array: `[1, 3, 4, 9, 10, 14, 19, 23]`

| Iteration | `l` | `h` | `mid = l + (h-l)/2` | `arr[mid]` | Comparison with Target (19) | Next Action |
| :---: | :---: | :---: | :---: | :---: | :---: | :--- |
| **1** | 0 | 7 | 3 | 9 | $9 < 19$ | Discard left: `l = 3 + 1 = 4` |
| **2** | 4 | 7 | 5 | 14 | $14 < 19$ | Discard left: `l = 5 + 1 = 6` |
| **3** | 6 | 7 | 6 | 19 | $19 == 19$ | **Target Found!** Exit. |

---

### 4. Complexity Analysis

- **Time Complexity:**
  - **Best Case: $O(1)$**  
    Target is exactly at the initial midpoint.
  - **Worst Case: $O(\log_2 n)$**  
    With each comparison, the search range is divided by 2. For an array of 1,000,000 elements, Binary Search needs at most $\approx 20$ comparisons!
  - **Average Case: $O(\log_2 n)$**
- **Space Complexity: $O(1)$**  
  Uses only three integer pointer variables (`l`, `h`, `mid`), operating in constant space.

---

### 5. Why `l + (h - l) / 2` instead of `(l + h) / 2`?
In C++, if `l` and `h` are very large numbers (e.g. near $2 \times 10^9$), their sum `l + h` can exceed the maximum value of a 32-bit signed integer and wrap around to a negative number (integer overflow). Writing `l + (h - l) / 2` calculates the exact same midpoint while guaranteeing that values never overflow.
