# Problem Title: Two Sum - Check if a Pair with Given Sum Exists (LeetCode 1 Variant)

## Problem Statement
Given an array of integers `arr` and an integer `target`, determine whether there exist **two elements** in the array such that their sum equals the `target`:
$$\text{element}_1 + \text{element}_2 = \text{target}$$

- Print `"Pair Exists!"` if such a pair is found.
- Print `"Pair Doesn't exist !"` if no such pair exists.

---

## Sample Examples

### Example 1
- **Input Array:** `arr = [1, 3, 4, 5, 7, 8, 99, 234]`
- **Target:** `239`
- **Output:** `Pair Exists!`
- **Explanation:**  
  The pair $(5, 234)$ adds up to:
  $$5 + 234 = 239$$
  Since both elements exist in the array, the output is `Pair Exists!`.

### Example 2
- **Input Array:** `arr = [2, 7, 11, 15]`
- **Target:** `9`
- **Output:** `Pair Exists!`
- **Explanation:**  
  $2 + 7 = 9$. The target pair $(2, 7)$ exists.

### Example 3
- **Input Array:** `arr = [1, 3, 4, 5, 7]`
- **Target:** `20`
- **Output:** `Pair Doesn't exist !`
- **Explanation:**  
  No two numbers in the array add up to 20 (the maximum possible sum is $5 + 7 = 12$).

---

## Detailed Solution (In Simple English)

### 1. Intuition & Approach (Lookup by Complement)
A brute-force solution checks all possible pairs using two nested loops:
- For every element $i$, loop through every element $j$ to check if `arr[i] + arr[j] == target`.
- This takes $O(n^2)$ time, which is slow for large arrays.

#### The Smarter Look-Behind Approach:
If we are currently looking at a number $b$, what number $a$ do we need to make the target sum?
$$a = \text{target} - b$$
This required number $a$ is called the **complement**.

Instead of searching forward for $a$, we remember all numbers we have seen so far in a **Set (`set<int> s`)**:
1. For each number $b$:
   - Check if its complement $(\text{target} - b)$ is already in our set:
     - If `s.count(target - b) > 0`, it means we saw its matching partner earlier! We return `true` immediately.
   - If not found, insert current number $b$ into the set: `s.insert(b)`.
2. If we reach the end without finding any pair, return `false`.

---

### 2. How the C++ Code Works Step-by-Step

```cpp
#include<iostream>
#include<set>
using namespace std;

bool twoSum(int arr[], int target, int n) {
    set<int> s;

    for(int i=0; i<n; i++) {
        int b = arr[i];
        if(s.count(target - b) > 0) {
            return true;
        }
        s.insert(b);
    }

    return false;
}

int main()
{
    int arr[] = {1,3,4,5,7,8,99,234};
    int n = sizeof(arr) / sizeof(arr[0]);
    int target = 239;

    if(twoSum(arr, target, n)) {
        cout << "Pair Exists!";
    }
    else {
        cout << "Pair Doesn't exist !";
    }

    return 0;
}
```

1. **`twoSum()` Function**:
   - `set<int> s;`: Creates an ordered set (implemented as a self-balancing binary search tree in C++ STL).
   - `for(int i = 0; i < n; i++)`: Iterates through the array.
   - `int b = arr[i];`: The current element.
   - `s.count(target - b)`: Checks if the complement exists in the set:
     - If count $> 0$, returns `true`.
   - `s.insert(b);`: Stores $b$ so subsequent numbers can check against it.
   - If loop terminates without a match, returns `false`.
2. **`main()` Function**:
   - Calls `twoSum(arr, 239, 8)` and outputs whether the pair exists.

---

### 3. Step-by-Step Dry Run (Target = 239)

Array: `[1, 3, 4, 5, 7, 8, 99, 234]`

| Step (`i`) | Current $b$ | Needed Complement (`239 - b`) | Is in Set `s`? | Action | Set Contents After Step |
| :---: | :---: | :---: | :---: | :--- | :--- |
| `0` | 1 | 238 | No | Insert 1 | `{1}` |
| `1` | 3 | 236 | No | Insert 3 | `{1, 3}` |
| `2` | 4 | 235 | No | Insert 4 | `{1, 3, 4}` |
| `3` | 5 | 234 | No | Insert 5 | `{1, 3, 4, 5}` |
| `4` | 7 | 232 | No | Insert 7 | `{1, 3, 4, 5, 7}` |
| `5` | 8 | 231 | No | Insert 8 | `{1, 3, 4, 5, 7, 8}` |
| `6` | 99 | 140 | No | Insert 99 | `{1, 3, 4, 5, 7, 8, 99}` |
| `7` | 234 | 5 | **Yes (5 is in set!)** | **Pair found!** Return `true`. | - |

Output: **`Pair Exists!`** (Matching pair is $5 + 234 = 239$).

---

### 4. Complexity Analysis

- **Time Complexity:** $O(n \log n)$  
  - Inserting and looking up an element in `std::set` takes $O(\log n)$ time.
  - Across $n$ elements, the loop takes $n \times O(\log n) = O(n \log n)$.
  - *(Optimization Tip: Using `std::unordered_set` from `<unordered_set>` reduces lookup and insertion to $O(1)$ average time, achieving overall $O(n)$ runtime).*
- **Space Complexity:** $O(n)$  
  In the worst case, the set stores all $n$ elements.

---

### 5. Edge Cases
- **Same Element Twice:** Because we check `s.count(target - b)` **before** inserting $b$ into the set, an element cannot mistakenly pair with itself (e.g., if `target = 6` and array contains one `3`, it won't claim `3 + 3 = 6`).
- **Array with < 2 elements:** The loop completes and returns `false`.
